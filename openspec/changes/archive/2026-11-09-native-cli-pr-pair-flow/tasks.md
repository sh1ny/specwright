# Tasks

## Test map

Every scenario in all four deltas is mapped below. Red rows are planned new/changed checks; their named tests do not exist yet. Green rows carry unchanged behavior already covered by existing tests, including aliases retained when the temporary dispatch requirements are replaced. Green does not claim those tests were rerun during planning; the relevant groups must rerun them during apply.

During apply, green also marks delivered checks whose named file passes locally. A platform or runtime skip remains a skip and does not prove that branch passed; CI owns the remaining OS matrix.

The workflow tests cover all fourteen commands, all four pass operations, and success/refusal/unknown cases. They compare workflow decisions, effects and GitHub calls, not just return codes. The frozen oracle is evidence of the existing workflow. Incidental Python formatting/parser quirks may be replaced when concrete differences and coordinated producer/consumer contract tests prove the same product behavior under S2/D6. Identity, mutation guards, ownership and recovery are never normalized away. Before the final shim switch, evals call native entries through their NUL handoffs directly; shim routing tests prove the final switch separately.
