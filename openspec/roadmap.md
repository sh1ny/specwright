# Specwright Roadmap

Strategy: [openspec/strategy.md](strategy.md) · Architecture: [openspec/architecture.md](architecture.md)

Specwright already exists (0.1.8), so M1 is not a walking skeleton: it closes the gaps between the code and the architecture baseline that most often force a manual rescue. Issue numbers refer to sh1ny/specwright. Versions follow the pre-1.0 rule in [strategy.md](strategy.md#assumptions): one minor version per feature, configuration key or workflow change, and a patch version per fix.

## Now: M8 - Complete the native CLI migration

**Outcome:** every shipped script runs in `sw`, and Specwright needs neither bash nor Python for its own work (#148). The remaining scripts are ported one PR at a time behind ADR 0028's shims, with their existing JSON, exit-code, identity, process, journal and recovery contracts intact; the shims, the three `bounded.py` copies and the Python and bash prerequisites go last, once every port has proven parity. The user-approved amendment on 2026-11-08 adds an internal-call retrofit and a native external-tool launcher, so removing the scripts also removes their runtime dependencies.

Ported Specwright operations call one another through their Dart interfaces, without launching a shim, a script or another `sw` for ordinary internal work. Separate processes remain for the reviewer regex evaluator under the poll deadline (ADR 0022), the `sw __exec` bounded helper (ADR 0027) and external tools, including `git`, `gh`, `jj`, `but` and reviewer CLIs. Direct calls preserve each caller's existing deadline and byte bounds, exact argument bytes, target repository and refusal mapping. Where a caller already bounds a whole fenced operation, as `pr-pair.sh` does for its fenced Git reads, credential lookup, identity verification and the command share that budget. Other fenced calls keep their per-lookup bounds and an unbounded command. A token stays in the environment of the call it was verified for. Calls that were unbounded do not acquire a deadline as a side effect of this refactor.

**Exit criteria:**
- The PR, review, release and update operations use `sw`; their existing JSON, exit-code and workflow contracts are covered by the corresponding black-box evals on the three CI platforms. (agent)
- A fresh install and an update reach a working, checked `sw` on Linux, Windows and macOS without Python or bash, and an update keeps its recovery guarantees. (agent)
- No shipped skill calls a bash or Python script or gives the agent a command that needs bash syntax; the ported scripts, their shims and the `bounded.py` copies are removed, and the docs list no Python or bash prerequisite for Specwright's own work. (agent)
- `sw` starts itself only for the bounded helper and reviewer evaluation, and never starts a shipped script or Python for its own work. Running a different installed or downloaded `sw` to check its version and interface stays allowed. A launch-site allowlist over `cli/lib/src` covers callers of the process runners as well as the runners themselves; black-box evals run the ported commands with shipped scripts absent and failing `python` and `python3` first on `PATH`, on Linux, Windows and macOS. (agent)
- Direct fence evals pass on the three CI platforms for exact argument bytes, per-call token scope, target-repository checks, refusal mapping and each existing deadline, including termination of descendants where a whole operation was bounded, and no new deadline on `sw vcs` fenced commands. Reviewer regex evaluation remains separately killable at the poll deadline. (agent)
- `sw` starts no bash or sh for its own work: evals run the ported commands on the three CI platforms with failing `bash` and `sh` first on `PATH`, and record exact argument bytes at the external tool. The launch-site checks also reject absolute-path shell launches for Specwright's own work. External tools may use their own shells, including Git's credential helper; an explicitly requested fenced user command is still allowed to be a shell or interpreter. (agent)
- All M8 changes are archived on main and their releases are published. (agent)

**Changes** (in order; each about one PR):
1. `native-cli-pr-io` - port `as.sh`, `pr-reply.sh` and `pr-snapshot.sh` to `sw`, with the fenced identity and the exact reply bytes intact; carries #202.
2. `native-cli-pr-pair` - port the settings and policy side of `pr-pair.sh` (`identity`, `vcs`, `tier`, `context` and `policy`, with the strict settings reader they share) and `reviewers.py`.
3. `native-cli-pr-pair-flow` - port the 14 `pr-pair.sh` subcommands left in Python: `discover`, `expected`, `ensure-pr`, `closing-check`, `closed-check`, `link`, `pair-state`, `rounds`, `pass`, `cleanup-plan`, `branch-check`, `merge`, `delete-remote` and `item-issues`. Call ported fence and VCS operations directly through shared Dart interfaces, preserving the bounds and identity rules above; record the internal-call rule and the allowed isolation boundaries in an ADR, updating the architecture during apply. Add explicit `--project <code-checkout>` selection to the `pr-pair.sh` and `as.sh` shims for store-started calls. Retain the existing nested fence hop in non-Git `branch-check`/VCS `fetch-main` until change 4, forwarding the project selector without changing the target directory or login.
4. `native-cli-internal-calls` - retrofit the completed ports: replace the fence and login-resolution shim calls in `sw vcs` for Git, jj and GitButler, and the `--check-config` child and obsolete Python probe in `sw pr snapshot`, with native calls. State the evaluator's limit-message text without probing for an interpreter. Keep the bounded reviewer evaluator and process helper. Add the launch-site allowlist covering callers of the process runners, with only the allowed self-launches, binary checks and no shipped script in launch arguments. Add black-box evals that pass recording `as.sh` and `vcs.sh` sentinels through the scripts-directory handoff, prove neither runs on each former path and fail before the retrofit. Cover argument bytes, credentials, target repositories, unchanged deadlines and error mapping, apart from the stated probe and limit-message changes.
5. `native-cli-launcher` - start external tools without bash, before the remaining ports add more shell launches. A native launcher passes exact argument bytes, environment and working directory on every OS, preserving command lookup, exit 127, stdin, signal and deadline behavior without adding a deadline to unbounded calls. Replace the `mktemp`, `ln`, `sleep`, `date`, `getconf`, `pwd -P` and `cygpath` calls with native operations. Record an ADR adding to 0027 that defines argument encoding on each OS, MSYS-form path input and Windows commands that are extensionless scripts. Verify bounded and unbounded launch paths, long Windows arguments and non-UTF-8 POSIX bytes; test shell absence and exact tool input, preserving the required isolation boundaries above.
6. `native-cli-review` - port `review-run.sh`: reviewer routes, selection, isolation and result validation. Read VCS settings and call other ported Specwright operations in process; launch external tools through the native launcher.
7. `native-cli-release` - port `release.sh`: bump, check, notes, untagged and publish. Read VCS settings and call other ported Specwright operations in process; launch external tools through the native launcher; carries #211.
8. `native-cli-update` - port `scripts/update.sh` and complete the bootstrap, so an install needs only `sw`; call ported Specwright operations in the running version in process, while retaining checks of the downloaded binary's version and interface. Use the native launcher for external tools and replace `scripts/install-sw.sh` and the README install prompt's bash steps, defining how the first `sw` is downloaded and checked without bash.
9. `native-cli-retire-scripts` - define the direct CLI entry and byte-preserving argument contract in a successor to ADR 0028, then switch the skills to call `sw` directly. Replace `sw-path.sh` with resolution and version checking that need no script. Replace inline shell in skill text, including the gate lock in `specwright-branch` and `specwright-roadmap`, with `sw` commands. Replace printed `bash vcs.sh` and `bash as.sh` commands and obsolete script-existence checks; remove the shims, the `bounded.py` copies and the Python and bash prerequisites once parity is proven. Run the script-absent and interpreter-absent evals and update prerequisite documentation.

## Done

- **M7 - Native CLI foundation** (closed 2026-11-07; PRs #199, #200, #203, #204, #205, #207, #210; releases 0.21.0-0.27.0). All five exit criteria passed: ADR 0027 (superseding 0002) and ADR 0028 were reviewed and accepted; v0.27.0 ships five checked `sw` binaries with `SHA256SUMS`; the `cli` and eval matrices passed on the closing head on Linux, Windows and macOS, the Windows release suite on a re-run after a timing flake (#211). Learned: a frozen oracle copy of each script, run differentially against the port, made parity reviews short and caught Python-specific behaviour (`(?m)` anchors, code-point sorting, `os.walk` order) that unit tests missed; a port keeps the old script's defects for parity and files them (#206, #209) instead of fixing them mid-port; the two inserted design-quality changes (#197, #198) paid off, since every port's design cited the code it replaced; and Windows CI timing tests need headroom for the steps they do not bound.

- **M6 - Packs** (closed 2026-11-04; PRs #156, #158, #159, #160, #163, #165, #174, #179, #183, #187, #188, #195; releases 0.12.1-0.20.0). The closing-head eval matrix passed on Linux, Windows and macOS; the first shipped packs, user-verified tasks and roadmap decision modes are in place. Learned: pack installation and delivered instructions need complementary coverage; cross-platform GitButler coverage remains limited by upstream binary availability (#154); and the native CLI migration needs a distribution and process-runner spike before incremental replacement.

- **M5 - Commits and VCS backends** (closed 2026-10-31; PRs #129, #132, #135, #137, #142, #147, #149; releases 0.8.1-0.12.0). All nine exit criteria passed; the suites were verified by the Linux CI run of every suite on #149, not by a local full run. Learned: the Windows suites still take about 80 minutes after `fix-eval-gaps` cut them from about 140 (`evals/timings.md`), and three `test_git_backend` cases crash real `git` only on this Windows machine, so M6 opens with OS-matrix CI (#145) and local full runs stop; a backend with a shared work tree (GitButler) turns every read of settings or skills from the work tree into a trust question, which the reviews of `add-gitbutler-backend` found late and #150 and #151 track; Codex's security review on sh1ny/kehai#2 found that agent merge trusts the merge policy on the PR branch (#141), so M6 fixes that before packs add more project-supplied content; and eight gaps were filed during M5, so M6 again includes a gap-fix change.
- **M4 - Cost tier** (closed 2026-10-26; PRs #102, #104, #108, #112, #120, #126; releases 0.6.1-0.8.0). All six exit criteria passed. Learned: fifteen gaps were filed during M4 (#109-#125, less the PRs), mostly edge cases that reviews of `fix-deferral-followups`, `bound-pr-scripts` and `exact-eval-grader` found and that were filed as issues instead of fixed in those PRs, plus #118 from a dogfood project, so M5 opens with three gap-fix changes; the codex route still fails on Windows after #95 because a failing run discards codex's own error, so the next fix starts with diagnostics; the Haiku stress run found two wording gaps and one grader false negative and no model limit, so wording tests on the cheap tier are worth keeping; `evals/finish`, added by `fix-deferral-followups` (itself inserted mid-milestone), was not named in the criteria, so M5's criteria name it; and the six suites took about two and a half hours on Windows at about 215 ms per process launch, so M5 cuts launches per test (#127).
- **M3 - Distribution** (closed 2026-10-17; PRs #89, #90, #92, #96; releases 0.4.1-0.6.0). Seven of eight exit criteria passed; the user-verified dogfood update with a change in flight is deferred to #98, by the user's choice, because it can only run once a release is out and waiting for it would hold up M4. Learned: a user-verified check against a published release cannot pass before close, so later milestones list such checks as follow-ups instead of exit criteria; `safe-update-lifecycle` took six fix rounds, four past the limit, with each round finding a new lock or interruption race, so concurrency-heavy changes need race tests in the design, not just in review; the update suite takes about half an hour on Windows because it spawns a process per file operation; and seven gaps were filed during M3 (#91, #93, #94, #95, #97, #99, #100; the last two found by the first attempt at the deferred dogfood check), so M4 again opens with a gap-fix change.
- **M2 - Ship flow** (closed 2026-10-14; PRs #71, #73, #79, #82, #85; releases 0.1.12-0.4.0). Six of seven exit criteria passed; the user-verified dogfood run of the pre-ship review and agent merge is deferred to #86, by the user's choice, because it needs a full change in a dogfood project. Learned: the review-run.sh tests landed in a third suite, `evals/review-routes`, that the criteria did not name, so M3's criteria name all three; nine known gaps were filed during M2 (most found by the pre-ship and Codex reviews before merge), so M3 again opens with a gap-fix change; and graded agent evals must be re-run after late skill edits (the agent-merge evals were re-run at close for that reason).
